# 编排契约（Orchestration Contract）

> 平台无关的 3 个编排动词 + 4 平台适配表。**上游（team-lead / agents / portable）正文只写契约动词；平台专属语法只允许出现在本文件。** 新平台接入 = 适配表加一列，上游零改动（audit M2 解法）。

## 使用规则

1. 启动第一步：主理人读本文件适配表，确定当前宿主平台的动词映射，再进入 SOP Phase 1。
2. 上游 SOP（`research-analytics-team-team-lead.md`）以契约动词表述编排；具体平台语法（TeamCreate / spawn / SendMessage / subagent_type 等）查本表执行。
3. 契约动词语义不随平台变化；平台做不到时走「失败与降级适配」，不得静默改语义。
4. 本文件是薄契约（≤150 行）：只定义动词与映射，不复写 SOP、不复写 dmr 裁决标准。

## 契约动词（3 个）

### 1. `assemble` — 组队
- **语义**：为本次调研组建执行单元（成员集合 + 分域分工 + 预算份额分配），协作边界由主理人唯一持有。
- **前置**：Step 0 意图路由完成、参数卡就绪、快版单线程路径判定完成（快版默认不 assemble，见 team-lead §工程健壮性机制·0）。
- **后置**：成员就位、预算份额广播、来源池分域预分配发布。
- **铁律**：assemble 只能由主理人执行，严禁委派成员。

### 2. `dispatch` — 派单
- **语义**：向指定成员下发**有界任务**（角色卡要点 + 任务卡 + 参数卡快照 + 预算份额 + 回传格式约定）。
- **前置**：assemble 完成（或单线程路径已判定）；该成员的域无重复属主（分域预分配）。
- **后置**：成员开始执行；主理人挂起等待该单，不代写（挂起等待**不计**主理人空转；主理人空转 = 重复 dispatch 相同任务卡且零新增证据，对齐治理规范 §六.5）。
- **铁律**：任务卡必须自包含——接收方不依赖会话历史即可执行；跨成员信息流必须经主理人中转；任务卡内置重复止损——成员重复相同查询/URL **连续 ≥3 次** → 回滚该动作重采样，**不消耗采集轮次预算**（对齐治理规范 §六.5 回滚不占迭代预算）。

### 3. `collect` — 收编
- **语义**：收取成员**结构化摘要**（证据表 + 结论 + 置信标签 + 消耗计数），写入来源池，进入 Phase 2 裁决（两段式唯一证据入口）。
- **前置**：dispatch 已发出；成员完成或触发 checkpoint（剩余轮次 ≤20% / 预算预警）。
- **后置**：来源池登记（实体×域×Tier×日期）；矛盾入台账；预算账本核销。
- **铁律**：未 collect 的证据不得进入终稿；**承重结论**（进入终稿的负载性事实）在产生处附 E1 级证据（源 URL+层级+日期）随结构化摘要回传，不等终稿对抗审计倒推——Phase 2 裁决对承重结论只升不降（对齐治理规范 §二 E 子任务承重中间结果即时验证）；成员超时先入「待接管」裁决（见下节），证据不丢弃。

## 任务生命周期五态（主理人唯一维护）

| 状态 | 进入条件 | 备注 |
|---|---|---|
| pending | assemble 完成分域预分配、dispatch 未发 | 初始态 |
| active | dispatch 已发出、成员执行中 | 主理人挂起等待，不计空转（见 dispatch 后置） |
| completed | collect 完成、来源池已登记 | 终态（被重派覆盖为新行） |
| blocked | 暂停线触发（成员超时/无响应）= 待接管 | 走三分支裁决 |
| cancelled | 裁决③接受降级 / 用户中止 | 缺口入开放问题，证据保留 |

## 平台适配表（3 动词 × 4 平台）

| 契约动词 | WorkBuddy | Coze（设计态，未实测） | 单线程（快版默认） | TRAE（TraeWork/SOLO，会话级任务型） |
|---|---|---|---|---|
| `assemble` | 主理人 TeamCreate 建团队 + spawn 拉成员（subagent_type=成员 Agent ID） | 工作流编排：成员=工作流子节点/子会话，主节点持协作边界 | 不组队——主理人顺序扮演各角色（M3 铁律：免 TeamCreate/spawn，直跑 dmr Step 1/4/8） | 不建持久团队——协作边界即主会话；按研究子问题 spawn ≤3 子智能体（对齐 M4 L0 档），成员=单轮任务型返回，无持久 inbox |
| `dispatch` | Agent 工具调度 + SendMessage 下发任务卡（name/subagent_type 传成员 Agent ID） | 子会话 prompt 下发：**子会话不继承 Skills，参数卡必须内联**（角色卡要点+任务卡+dmr 裁决标准要点全部写进 prompt，不得假设子会话能加载 dmr） | 内联执行该成员职责段（预算份额内），无跨会话传递 | Agent 工具派发（subagent_type=explore/general_task，调研子任务用 explore 只读联网）+ 角色 `model` 档位 override；任务卡内联；并行 ≤3、独立盲评（M10） |

## TRAE 适配参数细则（dispatch / assemble / collect）

1. `assemble` 在 TRAE 不建持久团队/持久 inbox——协作边界即主会话；成员按**研究子问题**（非固定域分工）spawn，并行数 ≤3（对齐治理规范 M4 L0 档）。成员超时/无响应的 checkpoint 兜底退化为「返回时一次性摘要」，语义以本文件暂停线节为准。
2. `dispatch` 用 Agent 工具：`subagent_type` 传 explore（只读联网调研子任务）/ general_task 等；按角色建议 `model` 档位 override（对齐治理规范 M9：主=强推理、执行=default、验证/judge=异构模型家族，平台支持时）。
3. `collect` 解析子智能体返回入来源池；成员产出若为非结构化，按上表「失败与降级适配·collect」强制收取结构化摘要再入池。
4. 周期监测（模板 E）可由 TRAE 原生 Schedule 周期任务触发——assemble 时带上期快照与对账基准，走增量路径，禁止全量重写。

## 模型档位与降级标注（对齐治理规范 M9）

- `assemble` / `dispatch` / 裁决角色的模型档位分配与跨模型 `judge` 由宿主平台能力决定；平台仅为单一模型后端时，对抗审计 / 跨模型裁决**降级为同模自评**，并必须在方法论声明显式标注「对抗审计为同模自评」（禁止以同模自评静默冒充异构裁决）。
- 平台支持子任务级模型选择时（如 TRAE Agent 工具 `model` override），优先给验收 / 裁决角色配**异构模型家族**做跨模校验（对齐 M10 异构仲裁；WorkBuddy 同模型下按前款降级标注）。

## WorkBuddy 适配参数细则（dispatch / assemble）

1. Agent 工具的 `name` 参数传入成员的 **Agent ID**（MD 文件名，不含 `.md`）；`subagent_type` 传入相同值。禁止使用中文名或自创名称。
2. `assemble` = 主理人 TeamCreate 建团队 + spawn 各成员（subagent_type 同上）；协作边界由主理人声明，严禁委派成员建队。
3. `collect` = 解析成员 SendMessage 回传的结构化摘要；跨成员信息流必须经主理人中转（消息中转铁律）。
4. 超时账本口径：总墙钟 SLA 自 `assemble` 完成起算；快版单线程自首步执行起算。

## 失败与降级适配

| 契约动词 | 失败表现 | 降级动作 |
|---|---|---|
| `assemble` | 平台不支持团队原语 / 调度失败 | 整体降级单线程（异常路径，须披露）；快版本就单线程 |
| `dispatch` | 单成员派单失败 / 无响应 | 回收其预算份额，主理人接管该域采集并标注降级；不重派超过 1 次 |
| `collect` | 成员超时 / 输出非结构化 | 触发 checkpoint 兜底：强制收取结构化摘要（已采证据不丢弃），不足处在终稿披露 |

## 暂停线与待接管裁决（成员级失败语义）

成员超时 / 无响应时**不立即重试**：先固定现场，再由主理人裁决；**整批重跑一律禁止**。

1. **暂停线触发**：成员超时或无响应 → 冻结该成员任务（不再等、不代写、不整批重跑），先落**执行快照** = 预算消耗 + 来源池已回写增量 + 已产出条目数 + 未完成项清单（快照挂成员 checkpoint 回传；无 checkpoint 则按最后一次可见产物兜底）。
2. **标「待接管」**：该成员任务进入待接管态，快照与缺口随进度通报披露。
3. **主理人三分支裁决**（按序评估，只选其一）：

| 分支 | 动作 | 约束 |
|---|---|---|
| ① 清理重跑 | 对该成员重新 `dispatch` 同一任务卡 | 来源池已回写证据保留（重跑者从池消费，不重复拉源）；重跑消耗**全局余量**，不追加总封顶、不重新分配份额；同成员重跑 ≤1 次 |
| ② 人工接手 | 走介入窗口：向用户披露快照与缺口，等待裁决（继续降级 / 补充信源 / 中止） | 快版与免确认路径不适用（直接走③） |
| ③ 接受降级 | 按上表「失败与降级适配」收拢部分产物，缺口入开放问题 | 终稿方法论声明披露降级原因 |

4. **中途指令注入（运行中）**（对齐治理规范 §六.9 R14 部分有效性评估）：用户运行中新增指令/文件/范围调整 → 排队至当前成员 `collect` 边界注入（不打断进行中成员，跑完再收）；注入后先做**部分有效性评估**——来源池已回写证据与未受影响成员产出**保留复用**，仅对受影响域新增 `dispatch`（消耗全局余量，不重新分配份额），**禁止整批重跑**；触及调研主目标（课题/范围/实体清单变更）→ 回 Step 0 重新收敛参数卡（来源池保留，不因重收敛丢弃）。

> 状态对齐依据：Phase 1 成员无依赖 + 来源池强制回写/复用 → 单成员重跑天然安全；预算消耗是不可逆副作用，故重跑只花余量、永不追加封顶。

## Coze 特殊约束（适配表 Coze 列的展开）

1. **子会话不继承 Skills**：主会话加载的 dmr / 技能文件在子会话不可用——`dispatch` 的参数卡必须内联角色卡要点、任务卡、dmr 裁决标准（源分级 / ≥2 源确认 / 置信标签定义），子会话按内联文本执行，不得依赖重新加载。
2. **日程周期触发**：周报 / 月报 / 持续监测（模板 E）可由 Coze 日程触发器拉起——assemble 时带上上期快照与对账基准，走增量路径，禁止全量重写（对齐 dmr v2.4.0 模板 E）。
3. **编排边界**：Coze 工作流的节点拓扑即 assemble 结果；预算器数值（墙钟 / 搜索封顶）由主节点持有并随 dispatch 内联下发，子会话自计数并随 collect 回传核销。
