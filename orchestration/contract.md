# 编排契约（Orchestration Contract）

> 平台无关的 3 个编排动词 + 3 平台适配表。**上游（team-lead / agents / portable）正文只写契约动词；平台专属语法只允许出现在本文件。** 新平台接入 = 适配表加一列，上游零改动（audit M2 解法）。

## 使用规则

1. 启动第一步：主理人读本文件适配表，确定当前宿主平台的动词映射，再进入 SOP Phase 1。
2. 上游 SOP（`research-analytics-team-team-lead.md`）以契约动词表述编排；具体平台语法（TeamCreate / spawn / SendMessage / subagent_type 等）查本表执行。
3. 契约动词语义不随平台变化；平台做不到时走「失败与降级适配」，不得静默改语义。
4. 本文件是薄契约（≤150 行）：只定义动词与映射，不复写 SOP、不复写 dmr 裁决标准。

## 契约动词（3 个）

### 1. `assemble` — 组队
- **语义**：为本次调研组建执行单元（成员集合 + 分域分工 + 预算份额分配），协作边界由主理人唯一持有。
- **前置**：Step 0 意图路由完成、参数卡就绪、快版单线程路径判定完成（快版默认不 assemble，见 team-lead §工程健壮性机制·0）。
- **后置**：成员就位、预算份额广播、来源池分域预分配发布。
- **铁律**：assemble 只能由主理人执行，严禁委派成员。

### 2. `dispatch` — 派单
- **语义**：向指定成员下发**有界任务**（角色卡要点 + 任务卡 + 参数卡快照 + 预算份额 + 回传格式约定）。
- **前置**：assemble 完成（或单线程路径已判定）；该成员的域无重复属主（分域预分配）。
- **后置**：成员开始执行；主理人挂起等待该单，不代写。
- **铁律**：任务卡必须自包含——接收方不依赖会话历史即可执行；跨成员信息流必须经主理人中转。

### 3. `collect` — 收编
- **语义**：收取成员**结构化摘要**（证据表 + 结论 + 置信标签 + 消耗计数），写入来源池，进入 Phase 2 裁决（两段式唯一证据入口）。
- **前置**：dispatch 已发出；成员完成或触发 checkpoint（剩余轮次 ≤20% / 预算预警）。
- **后置**：来源池登记（实体×域×Tier×日期）；矛盾入台账；预算账本核销。
- **铁律**：未 collect 的证据不得进入终稿；成员超时只降级不丢弃。

## 平台适配表（3 动词 × 3 平台）

| 契约动词 | WorkBuddy | Coze | 单线程（快版默认） |
|---|---|---|---|
| `assemble` | 主理人 TeamCreate 建团队 + spawn 拉成员（subagent_type=成员 Agent ID） | 工作流编排：成员=工作流子节点/子会话，主节点持协作边界 | 不组队——主理人顺序扮演各角色（M3 铁律：免 TeamCreate/spawn，直跑 dmr Step 1/4/8） |
| `dispatch` | Agent 工具调度 + SendMessage 下发任务卡（name/subagent_type 传成员 Agent ID） | 子会话 prompt 下发：**子会话不继承 Skills，参数卡必须内联**（角色卡要点+任务卡+dmr 裁决标准要点全部写进 prompt，不得假设子会话能加载 dmr） | 内联执行该成员职责段（预算份额内），无跨会话传递 |
| `collect` | 成员回传消息 → 主理人解析结构化摘要 → 写入来源池 | 子会话产物节点解析 → 摘要回写主节点 → 入池 | 产出直接写入来源池（Phase 2 裁决唯一入口） |

## WorkBuddy 适配参数细则（dispatch / assemble）

1. Agent 工具的 `name` 参数传入成员的 **Agent ID**（MD 文件名，不含 `.md`）；`subagent_type` 传入相同值。禁止使用中文名或自创名称。
2. `assemble` = 主理人 TeamCreate 建团队 + spawn 各成员（subagent_type 同上）；协作边界由主理人声明，严禁委派成员建队。
3. `collect` = 解析成员 SendMessage 回传的结构化摘要；跨成员信息流必须经主理人中转（消息中转铁律）。
4. 超时账本口径：总墙钟 SLA 自 `assemble` 完成起算；快版单线程自首步执行起算。

## 失败与降级适配

| 契约动词 | 失败表现 | 降级动作 |
|---|---|---|
| `assemble` | 平台不支持团队原语 / 调度失败 | 整体降级单线程（异常路径，须披露）；快版本就单线程 |
| `dispatch` | 单成员派单失败 / 无响应 | 回收其预算份额，主理人接管该域采集并标注降级；不重派超过 1 次 |
| `collect` | 成员超时 / 输出非结构化 | 触发 checkpoint 兜底：强制收取结构化摘要（已采证据不丢弃），不足处在终稿披露 |

## Coze 特殊约束（适配表 Coze 列的展开）

1. **子会话不继承 Skills**：主会话加载的 dmr / 技能文件在子会话不可用——`dispatch` 的参数卡必须内联角色卡要点、任务卡、dmr 裁决标准（源分级 / ≥2 源确认 / 置信标签定义），子会话按内联文本执行，不得依赖重新加载。
2. **日程周期触发**：周报 / 月报 / 持续监测（模板 E）可由 Coze 日程触发器拉起——assemble 时带上上期快照与对账基准，走增量路径，禁止全量重写（对齐 dmr v2.4.0 模板 E）。
3. **编排边界**：Coze 工作流的节点拓扑即 assemble 结果；预算器数值（墙钟 / 搜索封顶）由主节点持有并随 dispatch 内联下发，子会话自计数并随 collect 回传核销。
